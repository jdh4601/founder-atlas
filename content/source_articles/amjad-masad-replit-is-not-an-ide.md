## IDE보다 REPL에 가까운 도구

Replit이라는 이름은 ‘REPL(Read Eval Print Loop)’에서 나왔다. REPL은 데이터를 읽고 평가한 뒤 출력하며 프로그램과 상호작용할 수 있게 해주는 기초적인 언어 도구로, 오늘날 대부분의 프로그래밍 언어와 개발 환경에서 찾아볼 수 있다.

![Read-Eval-Print 순환 구조를 보여 주는 REPL 도식](</figures/amjad-masad-replit-is-not-an-ide/web-1.jpg> "Read, Eval, Print 세 단계가 화살표로 이어진 순환 도식입니다. 입력한 식 (+ 7 3)을 읽어 JS로 평가한 뒤 결과 10을 출력하는 과정을 보여 주며, 문단이 설명하는 REPL의 동작 방식을 뒷받침합니다. 출처: learn-clojurescript.com")

개발 환경을 REPL에서 IDE까지 이어지는 하나의 연속선으로 본다면, Replit은 IDE보다 REPL 쪽에 더 가깝다. 개념을 빠르게 검증하고 아이디어를 탐색하기 위한 도구이기 때문이다. 현재 마케팅 페이지에서 Replit을 ‘온라인 IDE’라고 설명하는 것은 Replit이 잘 알려지지 않았을 때 필요했던 선택이지만, 이 표현은 곧 바뀔 예정이다.

## 코딩을 다시 즐겁게

Replit은 현대 소프트웨어 개발이 고된 과정으로 변한 데 대한 반응이기도 하다. 많은 개발자가 빌드를 기다리고, 테스트를 실행하고, 린터와 씨름하고, 프레임워크를 설정하는 데 시간을 보낸다. Replit은 프로그래밍의 기본으로 돌아가 코딩을 다시 즐겁게 만들려는 시도다.

우리가 지향하는 것은 전체 개발 생애주기를 단순한 인터페이스 하나로 압축하는 일이다. 코드를 작성하고 한 번만 클릭하면 곧바로 서비스가 공개된다. Multiplayer를 이용하면 이 모든 과정을 다른 사람들과 실시간으로 함께할 수도 있다.

![Multiplayer 기능이 켜진 온라인 코드 편집기 화면](</figures/amjad-masad-replit-is-not-an-ide/web-2.jpg> "왼쪽 Multiplayer 패널에는 여러 사용자가 참여해 채팅하는 모습이 보입니다. 가운데에는 main.py 코드 편집기, 오른쪽에는 실행 결과와 공개 주소가 있어서, 코드를 작성하고 실행하면서 다른 사람들과 실시간으로 함께 작업한다는 문단의 내용을 보여 줍니다. 출처: blog.replit.com")
