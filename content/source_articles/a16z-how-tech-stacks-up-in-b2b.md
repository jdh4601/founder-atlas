## 기업 규모와 업종이 가른 기술 선택

2020년 12월, 포춘 500·글로벌 2000·SaaS 50 기업의 기술 리더들에게 현재 사용하는 도구와 향후 12~24개월 안에 도입할 도구를 물었다. 조사 범위는 클라우드 컴퓨팅, 데브옵스와 애자일 개발, 데이터 인프라, AI·머신러닝, 기업용 애플리케이션과 협업 도구, 보안이었다. 소프트웨어, IT 서비스, 금융, 제조, 제약, 미디어 등 30개 업종에서 107명이 응답했다.

응답을 ZoomInfo 데이터와 대조하자 기업은 대체로 두 집단으로 나뉘었다. 작고 민첩한 기업은 파괴적 혁신 가능성이 큰 신생 도구를 빠르게 도입하는 반면, 규모가 크고 역사가 오래된 기업은 오랫동안 기업 시장을 지켜온 플랫폼을 선호했다. 익숙한 문화적·세대적 차이지만, 이번 결과는 그 간극이 실제 기술 선택에서 어느 정도로 나타나는지 수치로 보여준다.

분석에서는 직원 2만5,000명 초과 기업을 대기업, 5,000명 미만 기업을 소기업으로 정의했다. 규모만으로 모든 위험 선호도를 설명할 수는 없으며 업종별 경향을 모두 포괄한 조사도 아니다. 다만 민첩하고 파괴적인 기술 기업과 보수적이며 규제가 강한 은행·금융서비스·보험 기업을 비교하면 서로 다른 요구를 확인할 수 있었다.

조사를 관통하는 흐름은 다섯 가지다. 클라우드는 이미 변곡점을 지났고, 핵심 워크로드와 애플리케이션은 분산되고 있다. 데이터는 새로운 소프트웨어가 되었으며 AI는 더 많은 기업이 활용할 수 있는 기술로 바뀌고 있다. 원격근무 역시 지속될 가능성이 커졌지만, 그만큼 보안 위험과 제로 트러스트 체계의 필요성도 확대됐다.

## 클라우드는 보편화됐지만 전환 속도는 다르다

클라우드 도입에서는 기업 간 문화적·세대적 차이가 특히 분명했다. 기술 기업 응답자의 62%는 애플리케이션 워크로드의 절반 이상을 퍼블릭 클라우드에 올렸다. 같은 수준으로 클라우드를 이용하는 금융 기업은 25%에 불과했고, 금융 기업의 42%는 퍼블릭 클라우드에 배치한 워크로드가 10% 미만이었다.

![업종별 퍼블릭 클라우드 이용률 비교](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_2-e1618158070254-990x1024.png> "기술 기업은 금융 기업보다 애플리케이션 워크로드를 퍼블릭 클라우드로 이전한 비율이 높다. 출처: a16z")

규모에 따른 격차도 컸다. 소기업의 78%가 워크로드의 절반 이상을 퍼블릭 클라우드에서 운영한 반면 대기업에서는 그 비율이 24%였다. 오히려 대기업의 29%는 퍼블릭 클라우드에서 운영하는 애플리케이션이 10%에도 미치지 못했다. 그럼에도 클라우드는 업종 전반에서 보편적인 기반으로 자리 잡았고, 대부분의 기업은 앞으로 몇 년 동안 더 많은 애플리케이션을 이전할 것으로 예상했다.

주요 공급자는 AWS, Microsoft, Google이지만 대부분의 기업은 하나 이상의 공급자를 사용한다. 멀티클라우드는 위험과 특정 공급자 종속을 줄이고 규제 요건에 대응하는 데 도움이 되지만, 여러 클라우드에 걸친 업무를 관리할 도구가 필요하다는 뜻이기도 하다. 비용 추적·최적화 도구 시장은 분산돼 있고 클라우드 백업 도구의 활용도도 낮았다.

## 분산 환경의 표준으로 자리 잡은 쿠버네티스

핵심 워크로드가 쿠버네티스 환경으로 이동하면서 거의 모든 기능이 클라우드 네이티브 방식으로 다시 만들어지고 있다. 전 세계에 분산된 애플리케이션은 미디어와 이커머스 같은 대형 산업에도 영향을 미치기 시작했고, 더 지능적이고 안전한 네트워크 구조를 요구한다.

코드를 배포하고 사용자에게 영향을 주는 문제를 해결할 때는 속도와 민첩성이 중요하다. 응답 기업 대부분은 매주 또는 매월 여러 차례 코드를 배포하고 개발자 성과를 추적하는 도구를 사용했다. 서비스 장애가 발생해도 대체로 몇 시간이나 며칠 안에 문제를 해결했다. GitHub와 Jenkins 같은 데브옵스 도구는 업계 전반의 기본 선택지가 됐다.

컨테이너 관리 도구를 하나 이상 사용하는 비율은 대기업이 70%, 소기업이 54%였다. 대기업 사용 사례에는 언제나 쿠버네티스가 포함됐으며, 전체 응답자의 50%가 쿠버네티스를 사용했다. Amazon ECS는 23%, Docker Swarm은 16%였다. 쿠버네티스 사용자가 선택한 실행 환경은 AWS가 63%로 가장 많았고 Microsoft Azure 46%, Google Cloud Platform 40%가 뒤를 이었다.

서버리스 기술에서도 AWS가 32%로 선두였으며 Azure Cloud가 20%, GCP가 14%를 기록했다. 클라우드 인프라를 주도하는 세 사업자가 컨테이너와 서버리스 실행 플랫폼에서도 중심을 차지한 셈이다.

## 데이터가 새로운 소프트웨어가 되다

5년 전에는 시스템이 주로 개발자가 작성한 코드의 결과물이었다면, 이제 시스템은 투입되는 데이터를 중심으로 만들어진다. AI가 기존에 개발자의 몫이던 일부 프로그래밍 작업까지 수행하기 시작하면서 개발자는 소스 코드만큼이나 데이터를 다루게 됐다. 소프트웨어 개발 도구 체인에 버금가는 데이터 인프라와 데이터 개발 도구 체인의 성장은 소프트웨어를 만드는 방식 자체를 바꿀 가능성이 있다.

기업의 선택지는 Snowflake와 Databricks 같은 데이터 인프라 기술부터 Apache Kafka 같은 스트리밍 도구, Informatica 같은 분석 플랫폼까지 폭넓었다. 그중 Databricks와 Snowflake의 인기가 가장 높았지만, 워크플로 관리에는 맞춤형 내부 도구를 사용하는 기업이 많았다.

금융 기업에서는 특히 Databricks를 비롯한 데이터 레이크로 향하는 흐름이 강했다. 금융 기업은 데이터의 비일관성과 정리되지 않은 상태를 더 자주 문제로 꼽았고, 기술 기업은 비정형 데이터를 더 우려했다. 금융 기업은 향후 12~18개월의 핵심 과제로 데이터 거버넌스와 계보 관리, 데이터 과학 플랫폼 개선을 지목했지만 실제 거버넌스와 데이터 출처 관리 도구의 사용은 매우 적었다.

## AI 활용은 빠르게 늘고 대기업이 앞선다

AI·머신러닝은 대부분의 기업에 아직 비교적 새로운 영역이지만 빠르게 발전하고 있다. 응답 기업 대다수는 이미 어느 정도 AI를 사용하고 있으며 견고한 데이터 과학·AI 조직도 갖추고 있었다. 현재 운영 중인 모델은 5개 미만인 경우가 가장 많았지만, 다수의 응답자는 향후 12개월 안에 프로덕션 모델이 30개를 넘을 것으로 내다봤다.

![현재와 향후 AI 모델 수 비교](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_6-e1618196004519-1024x917.png> "현재 운영 중인 AI·머신러닝 모델은 5개 미만인 기업이 많지만, 다수는 향후 12개월 안에 30개를 넘을 것으로 예상한다. 출처: a16z")

모델을 실제 서비스에 배포하는 속도는 여전히 느려서 일반적으로 1주 이상, 6개월 미만이 걸렸다. AI·머신러닝 프로젝트가 가장 활발하게 진행되는 영역은 제품과 엔지니어링이었다. 새로운 도구와 표준화된 데이터 수집·변환 스키마는 복잡한 모델을 매번 맞춤형으로 운영해야 했던 장벽을 낮추고, 더 많은 기업이 제품에 AI를 도입할 길을 열고 있다.

![AI 모델의 프로덕션 배포 기간](<https://a16z.com/wp-content/uploads/2023/04/Updated-AI-survey-e1618249363458-1024x799.png> "AI·머신러닝 모델을 프로덕션에 배포하는 데는 일반적으로 1주 이상 6개월 미만이 걸린다. 출처: a16z")

기술 기업은 2021년에 다른 업종보다 데이터 과학과 AI·머신러닝 인력을 더 많이 채용할 계획이었다. 그러나 실제 모델 활용에서는 대기업이 소기업보다 앞섰다. 직원 2만5,000명 초과 기업의 56%가 이미 30개 이상의 AI 모델을 프로덕션에서 운영한 반면, 직원 5,000명 미만 기업에서는 그 비율이 22%였다.

![기업 규모별 AI 모델 활용 비교](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_8-e1618196097904-1024x302.png> "대기업은 소기업보다 프로덕션에서 AI·머신러닝 모델을 훨씬 많이 활용한다. 출처: a16z")

AI 모델을 실행하는 퍼블릭 클라우드로는 AWS가 가장 널리 쓰였다. 다만 금융 기업의 53%는 모델을 자체 인프라에서 운영했으며, 전체 응답자의 온프레미스 운영 비율은 23%였다.

## 원격근무가 드러낸 협업 도구의 세대 차이

팬데믹으로 많은 사람이 원격근무를 하면서 화상회의, 메시징, 협업 소프트웨어의 중요성이 어느 때보다 커졌다. 앞으로 일반 업무 도구에도 개발자가 오래전부터 사용해 온 버전 관리, 댓글, 토론 기능이 실시간·비동기 협업의 기본 요건으로 자리 잡을 가능성이 크다. 파일 공유와 의사결정 기록, 토론 보존을 위해 SaaS 도구끼리 정보를 전달해야 하므로 API의 중요성도 커진다.

전체 응답자의 43%가 Microsoft Office 365와 Exchange를 사용해 가장 높은 비중을 보였다. Gmail은 31%, Box는 14%, Dropbox는 13%였다. 그러나 기술 기업의 47%가 Gmail을 선호한 반면 금융 기업의 Gmail 사용률은 12%에 그쳤다. 금융 기업과 대기업은 약 60%가 Microsoft 도구를 사용했지만 기술 기업과 소기업에서는 약 3분의 1만 사용했다. 특정 생태계에 대한 충성도는 강하지 않아 Gmail 사용 기업 가운데 Google Cloud IaaS도 이용하는 곳은 3분의 1뿐이었다.

메시징에서는 Microsoft Teams가 38%로 가장 많이 사용됐으며 금융 기업과 대기업에서 특히 강했다. Slack은 34%로 근소한 차이의 2위였고 기술 기업과 소기업에서 널리 쓰였다. Google Hangouts는 23%, Facebook Workplace는 8%였다. 프로젝트 관리 도구에서는 Jira가 전체 응답자의 45%로 압도적인 선택을 받았다. 기업용 애플리케이션 중에는 Salesforce가 가장 흔했으며, 대기업에서는 ServiceNow도 Salesforce만큼 많이 사용됐다.

화상회의 도구의 격차는 더욱 컸다. Zoom은 전체의 37%, 기술 기업의 53%, 소기업의 57%가 사용해 경쟁 제품보다 거의 두 배 많이 쓰였다. Google Meet은 전체의 20%였지만 금융 기업에서는 6%에 불과했다. WebEx의 전체 사용률은 19%였으나 대기업에서는 46%, 기술 기업에서는 6%였다. 화상회의용 Microsoft Teams는 전체의 14%, 기술 기업의 4%가 사용했다.

## 보안 투자는 늘고 제로 트러스트 전환은 빨라진다

사업 운영과 직원의 업무가 온라인으로 옮겨가면서 데이터와 개인정보 보호는 더욱 중요한 과제가 됐다. 기업이 가장 우려한 것은 데이터 보안이었고, 역할 기반 접근 제어와 거버넌스, 위험 관리, 규정 준수가 뒤를 이었다. 클라우드 보안에서는 구성 관리가 가장 큰 관심사였다.

![기업의 주요 보안 우려 사항](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_12-e1618196339513-1024x597.png> "기업의 가장 큰 우려는 데이터 보안이었으며 역할 기반 접근 제어와 거버넌스, 위험 관리, 규정 준수가 뒤를 이었다. 출처: a16z")

가장 안전한 클라우드 공급자를 묻자 전체 응답자의 30%가 AWS, 25%가 Microsoft를 선택했다. 그러나 대기업은 Microsoft를 선택한 비율이 46%로 훨씬 높았다. GCP를 가장 안전하다고 본 대기업도 29%로, 전체 응답자의 13%보다 높았다.

![가장 안전하다고 평가된 클라우드 공급자](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_13-e1618196398399-1024x426.png> "전체 응답에서는 AWS가 가장 안전한 클라우드 공급자로 꼽혔지만, 대기업은 Microsoft를 선택하는 경향이 더 강했다. 출처: a16z")

많은 기업이 기존 보안 체계의 일부를 개선하려 했고, 원격근무 환경의 보안을 유지할 방법도 검토했다. 전체 기업의 58%가 직원이 집에서 개인 기기를 사용하는 것을 허용했다. 기술 기업에서는 59%가 허용했지만 금융 기업에서는 33%에 그쳤다. 향후 12~18개월 동안 보안 지출을 늘리겠다는 응답은 전체의 3분의 2였으나 대기업에서는 절반이었다.

![원격근무자의 개인 기기 사용 허용 현황](<https://a16z.com/wp-content/uploads/2023/04/a16z_Analysis-Graphs_11-e1618196423562-1024x631.png> "대부분의 기업은 원격근무자가 집에서 개인 기기를 쓰도록 허용했지만, 금융 기업의 허용 비율은 33%에 그쳤다. 출처: a16z")

2020년의 변화는 기업의 규모와 업종에 따라 서로 다른 영향을 미쳤다. 하지만 사업 방식이 흔들린 범위가 워낙 컸기 때문에 모든 기업에는 미래에 빠르게 적응할 통찰력과 유연성이 필요해졌다. 이 조사 결과는 각 기업이 현재의 기술 스택을 가늠하고 앞으로의 구조를 설계하는 데 참고할 수 있는 하나의 기준을 제시한다.
